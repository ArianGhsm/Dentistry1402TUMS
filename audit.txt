[1) Architecture Summary]
- The project is a static multi-page app/PWA, not an SPA.
- Routing is folder-based under `public_html`.
- UI stack is vanilla HTML/CSS/JS.
- Data/auth are PHP endpoints backed by JSON/CSV storage.
- Most pages share header/theme/PWA/auth shell.
- `/chat/` is intentionally a dedicated full-screen module with shared bottom-nav disabled.
- RTL/Persian behavior is first-class across markup, locale formatting, and chat layout.

[3) What Already Exists]
- Shared site auth foundation exists and is active (`dent1402_session`, shared user store, `/api/auth_api.php`, `window.Dent1402Auth`).
- Messenger already consumes shared auth state.
- Bottom-nav is shared and auth-aware, intentionally disabled on landing/chat.
- Messenger already has baseline interaction features (polling, reply/edit/delete/reactions/pin/mute/context actions/member sheet/grouped bubbles/mobile long-press/mod controls).
- Grades has dashboard behavior (guard/loading/summary/per-course rows/class average/rank/refresh/logout hooks).
- Account/profile flows exist (login/profile fields/password change/current-user panel/owner representative management).
- Role model exists (`owner`, `representative`, `student`) with role-based chat moderation.
- Shared tokenized styling, dark mode, safe-area support, mobile breakpoints, and RTL/fa-IR foundations exist.

[4) What Is Missing]
- No true avatar/photo upload and shared avatar storage model.
- Chat is not yet Telegram-grade in infrastructure:
  - no conversation list/search/media-file messages/voice
  - no read state/presence/delivery state
  - no real-time transport
- Shared page-layout abstraction is still duplicated across routes.
- Current-user identity model is still narrow.
- Admin tooling is limited.
- `chat_api.php` still has redundant auth-like actions (`login/logout/me`) that duplicate shared auth surface.

[5) Boundary Contract]
- Telegram-grade upgrades must apply to `/chat/` and supporting identity/profile pieces needed by chat.
- `/app/`, `/grades/`, `/exams/`, `/notes/`, `/resources/`, and account/admin must remain domain-specific (not chat-like).

[6) Auth Foundation Decision]
- Existing shared login is the foundation and must remain the only public auth contract.
- `auth.js -> /api/auth_api.php -> auth_store.php -> PHP session` is source of truth.
- Chat-local auth duplication should be treated as legacy and not expanded.

[7) Clean Implementation Order]
1. Lock auth boundary around shared auth contract.
2. Define shared user identity contract (role/profile/moderation/avatar-ready fields).
3. Upgrade messenger backend model and performance path.
4. Upgrade `/chat/` UI model and ergonomics (mobile-first).
5. Polish non-chat surfaces without importing chat metaphors.
6. Final cross-cutting sweep: RTL, dark mode parity, safe-area behavior, PWA/offline rules, token cleanup.

[8) Integrity Rules To Preserve]
- No false-success states across toast/list/open/state sync.
- No persistence claims without canonical shared storage sync.
- Persian UI text, numbers, date/time must remain locale-correct by default.
- Avoid bidi-unsafe CSS patterns unless explicitly justified.
